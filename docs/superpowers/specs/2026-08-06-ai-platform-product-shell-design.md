# AI Platform Mini 产品化前端设计

## 背景

当前项目已经具备真实的 Chat SSE、Agent SSE、Agent Trace、Tool Call、RAG 来源、API Key 管理和管理员用量审计能力，但默认页面直接进入工程控制台，首屏缺少产品定位和演示路径。目标不是添加虚假业务数据，而是让面试官在 30 秒内理解平台能力，并在 3～5 分钟内完成一次可讲解的真实演示。

## 目标

1. 默认进入平台概览，而不是直接进入聊天控制台。
2. 用统一的平台外壳承载概览、智能对话、Agent 工作流、Prompt Studio、模型目录和管理员后台。
3. 保留现有真实请求逻辑与可访问性语义，不改变 Chat/Agent SSE 和 Trace 的数据边界。
4. 展示后端真实提供的模型列表；没有对应后端能力的启动、停止、删除等动作不做假按钮。
5. Prompt 模板以浏览器本地存储为边界，点击模板可以把演示问题带入真实 Console。
6. 未配置 API Key 或 RAG 未启用时，页面给出清晰的状态说明，而不是伪造运行成功。

## 视觉方向

采用浅色工作台风格：冷白卡片、深蓝文字、蓝紫渐变强调色和细边框。左侧导航表达平台结构，Dashboard 使用大标题、状态卡和快速演示卡片建立层级；Console 仍保留两栏对话与 Trace，但减少“阶段开发记录”式标题，改成面向用户的产品文案。

## 页面结构

### 概览

- 品牌标题和平台副标题。
- 后端在线状态、模型数量、Agent Trace、RAG 状态四个状态卡。
- 快速演示入口：智能问答、Agent 工作流、知识库问答、Prompt Studio。
- 一条 React → FastAPI → Agent Runtime → Ollama 的架构链路。
- 所有数值均使用真实可确认的信息或明确标记为“待配置”，不使用虚假请求量。

### 智能对话 / Agent 工作流

- 复用当前真实 Console。
- 使用产品化标题、模式标签、快速提示词和 API Key 状态说明。
- 保留 Request ID、Run ID、Trace 步骤、Tool Call、RAG 来源和错误重试。

### Prompt Studio

- 内置四个可编辑模板：代码审查、技术总结、面试模拟、知识库问答。
- 编辑内容后可保存到 localStorage。
- “带入对话”按钮将模板中的演示问题写入 Console 草稿并跳转。

### 模型目录

- 通过现有 `/api/v1/models` 读取真实模型列表。
- 展示模型 ID、Provider、可用能力标签。
- 无 API Key 时提示需要配置普通用户 Key；加载失败时显示安全错误，不泄露后端原始异常。

### 管理员后台

- 继续复用现有 AdminDashboard。
- 平台导航提供入口，返回按钮回到概览。

## 非目标

- 本轮不新增 PDF 上传、数据库 Prompt 持久化、Ollama 模型启停删除接口。
- 不引入 Ant Design、shadcn 或其他 UI 依赖。
- 不改动后端 API 合约和 Agent/RAG 安全投影。
